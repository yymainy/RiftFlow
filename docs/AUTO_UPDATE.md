# 自动更新

Windows x64 桌面版启动后自动检查，并每四小时再次检查。网络检查失败一分钟后重试；关闭自动检查后不轮询更新服务。设置 → 应用 → 软件更新可手动检查、控制自动下载、忽略指定版本。

默认只检查并提示，点击下载后才获取 EXE；开启自动下载也不会强制重启。发现新版本时显示常驻通知，右上角出现更新图标。下载完成后提示就绪，可选择“重启完成更新”，或在正常退出软件时应用。取消会清除待应用任务。

使用现有 `/releases/v1/latest?lang=zh-CN` / `lang=en` 服务。Windows 包要求 `platform: win32`、`arch: x64`、EXE 文件名、HTTPS 下载地址、正整数 `size` 和 64 位 `sha256`。只安装严格高于当前版本的包。7z 与 ZIP 不作为自动更新输入。

下载在用户数据目录 `NewUpdates/portable-*/`，校验文件大小、SHA256 和 PE x64 标识。安装助手复制自当前运行的程序，无需额外打包 updater.exe。退出后助手先等待原进程结束，再在同目录准备新文件、备份旧 EXE、替换并启动新版；准备或替换失败保留旧版，启动失败恢复旧版。旧程序保留为 `*.backup-*.exe` 以便手动恢复。用户数据库、AI 自定义配置与设置不移动。

发布前必须按 PACKAGING.md 构建。将该构建的独立 `RiftFlow.exe` 作为更新资产，填入其真实大小、SHA256、不可变 HTTPS 下载地址与递增版本，分别发布两种语言的版本说明。ZIP 是手动分发包，不可把 ZIP 的散列填入 EXE 元数据。发布是独立操作，本地出包不会更新服务器或上传文件。

验证命令：在 riftflow-rs 运行 `cargo test -p riftflow-app --bin riftflow update`。构建后在仓库根运行 `node scripts/test-desktop-update.mjs`，测试独立配置目录下的启动检查、提示、忽略与去重，以及独立助手等待退出、替换、备份和启动；只修改测试目录，不更新正在使用的软件。测试只读取线上发布信息，不修改线上服务。
